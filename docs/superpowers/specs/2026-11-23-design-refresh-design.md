# 화면 디자인 새로 입히기 — 설계

## 하려는 것과 이유

지금 화면은 회색 바탕·청록 강조의 무난한 업무 화면이라, 포트폴리오로 보일 때 "완성된 제품" 인상이 약하다. getdesign.md의 DESIGN.md 몇 개(Mercury·Warp 등)를 켜 둔 앱에 입혀 비교한 끝에 다음 조합으로 정했다.

- **형태·글씨·배치는 Mercury**(은행 앱): Inter + Pretendard, 가는 제목, 큰 모서리 카드, 알약 딱지, 한 덩어리 사이드바, 위쪽 제목 띠, 옅은 바탕 위 카드
- **라이트 색은 웜 차콜**: 따뜻한 미색 바탕, 거의 검정에 가까운 따뜻한 차콜 강조, 링크만 페트롤
- **다크 색은 Warp**: 따뜻한 숯색 바탕, 크림 글씨·버튼, 링크는 따뜻한 청록

색이 상태 딱지와 링크에만 남아, 급한 것(빨강·노랑)이 어느 조합보다 잘 보이는 것이 업무 화면으로서 이 조합의 핵심이다.

## 목표

- 아래 값으로 라이트·다크 토큰을 바꾸고, 모든 화면이 토큰을 따라 바뀐다
- 셸 배치를 바꾼다: 한 덩어리 사이드바, 위쪽 제목 띠, 옅은 바탕 위 카드
- 글꼴을 Inter(라틴·숫자) + Pretendard(한글)로, 숫자는 폭 고정
- 라이트·다크를 오가도 같은 앱으로 느껴진다(같은 형태, 따뜻한 색 계열)

## 하지 않는 것

- 부품 라이브러리 교체(Mantine 등) — shadcn/ui + Tailwind 그대로, 규칙(토큰은 `globals.css`만, 부품은 `components/ui/`만)도 그대로
- 전환 전 EMR 창 안(`--emr-*` 토큰, `components/emr/emr-ui.tsx`) — 옛 프로그램 느낌이 의도라 손대지 않는다
- 화면 기능·문구·데이터 흐름 변경, 새 화면
- 백엔드 변경

## 실패로 보는 것

- 급한 상태(빨강 "30일 이내"·"급한 통화", 노랑 "판단 필요")가 사용자가 고른 시안보다 덜 보이게 되는 것. 딱지 하나하나는 지금보다 옅고(바탕색·테두리 없음·굵기 500) 그것은 시안에서 보고 고른 값이다 — 판단은 시안 스크린숏과 나란히 놓고 눈으로 한다
- 링크(누를 수 있는 곳)가 일반 글씨와 구분이 안 되는 것 — 앞선 시안에서 링크를 강조색(차콜)과 같게 두었더니 바로 가기 칩 날짜 링크가 묻혔다
- 라이트 모드에서 선택된 메뉴가 안 보이는 것
- 화면 하나라도 옛 모양(회색 바탕·청록)이 남는 것

### 글씨

- `--font-sans`: Inter(라틴·숫자) → Pretendard(한글) 순. 지금의 Noto Sans KR은 뺀다
- 숫자는 폭 고정(`font-feature-settings: "tnum"`) — 금액·건수 열이 줄 맞게
- 제목(h1~h3): 굵기 500, 자간 `-0.025em`

### 모양

- 카드·큰 덩어리(표 감싸개, 목록 카드) 모서리 16px
- 상태 딱지(warn·danger·ok·info): 알약 모양, 굵기 500, 테두리 없음, 점은 그대로 — `badge.tsx` variant에서 바꾼다(`--status-*-border` 토큰을 딱지 바탕과 같게 만들지 않는다 — 경고 띠 테두리가 사라진다) *(내 판단)*
- 버튼·입력 모서리는 `--radius`를 따른다

### 배치

1. **한 덩어리 사이드바**: 아이콘 줄과 목록 칸을 같은 면(위 사이드바 바탕)으로 칠하고 둘 사이 경계를 없앤다. 본문 쪽 오른쪽 끝에만 경계 한 줄. 목록 칸 접기·펴기, 좁은 화면의 열고 닫기는 지금 동작 그대로
2. **위쪽 제목 띠**: 화면마다 본문 맨 위에 있던 제목 `header`(h1 + 설명 p)를 본문 열 맨 위의 가로 띠로 옮긴다. 띠에는 위에서부터 공간 이름(작은 회색, 예: "업무"), 화면 제목(h1, 1.45rem), 설명(13px). 바탕 `--card`, 아래 경계 한 줄, 스크롤해도 위에 붙어 있다(sticky). 띠 좌우 여백은 본문과 같은 선
   - 좁은 화면(`md` 아래): 지금의 셸 위쪽 줄(메뉴 단추 + 이름)은 그대로 두고 띠는 그 아래에 붙지 않고(sticky 아님) 놓인다. 자료실·AI 평가의 가로 탭 줄은 지금 자리(띠 위) — 셸이 화면 내용보다 먼저 그린다 *(내 판단)*
   - "목록 펴기" 단추(목록 칸을 접었을 때 본문 왼쪽 위)는 띠 안 왼쪽으로 옮긴다 *(내 판단)*
   - 띠가 본문 열 끝까지 닿도록 본문의 최대 폭(`max-w-[90rem]`)은 없앤다 *(내 판단)*
   - 띠가 위에 붙으므로, 본문 안에서 위에 붙는 것들(`calls-view`·`chart-ocr-view`의 `lg:sticky lg:top-4` 칸)의 위 간격은 띠 높이만큼 내린다 — 설명이 여러 줄로 감기면 띠가 높아지므로 고정값이 아니라 띠의 실제 높이를 따른다
3. **옅은 바탕 위 카드**: 본문 바탕은 `--background`, 카드는 `--card` — 지금 카드인 것들이 그대로 떠 보인다. 표 감싸개는 바탕을 칠하지 않는다(행은 본문 바탕, 머리만 `--muted` — 고른 시안 그대로). 본문 위아래 여백은 띠 아래 28px부터

화면별:

- 업무·자료실·AI 평가의 11개 화면(`app/(portal)/*/page.tsx`의 `<header>`): 모두 위 띠로
- AI 비서: 띠를 두지 않는다(사용자 결정 — 시안 비교). 시작 화면은 가운데 큰 제목이 이미 있고, 대화 화면은 띠 제목이 첫 질문 말풍선과 같은 문장이라 겹친다. 그래서 띠는 화면마다 쓰는 공용 부품으로 만들 수 있다(셸이 대화 제목을 알 필요 없음)
- EMR 공간: 띠를 두지 않는다. 사이드바(한 덩어리 아이콘 줄)와 토큰 색만 새 모양을 따르고, EMR 창과 `components/emr/`의 카드 모서리·소제목 굵기는 그대로 *(내 판단)*

## 확인한 것

- 링크는 `text-link`(`--link`) 한 토큰을 15곳이 쓴다(환자 요약·통화 상세·오늘·검색 결과·문서 패널·EMR 설명 카드·AI 비서 바로 가기 칩 등) — `--link`만 바꾸면 모두 같이 바뀐다
- 상태 딱지는 `components/ui/badge.tsx`의 `warn`·`danger`·`ok`·`info` variant, 점은 `StatusDot`
- 시안(켜 둔 앱에 덮어쓴 CSS)에서 라이트 AI 비서의 질문 말풍선(`bg-muted`)이 새 본문 바탕과 거의 같은 색이 되어 묻혔다 — 말풍선은 바탕과 구분되는 면이어야 한다
- e2e(`frontend/e2e/`)는 화면 모양(스크린숏·클래스)을 비교하지 않는다. 제목 띠로 옮겨도 h1은 남아야 한다(`getByRole("heading")`를 쓰는 테스트가 있다)

## 지켜야 할 규칙

- 색·모서리·글꼴·그림자는 `frontend/app/globals.css` 토큰으로만, 부품은 `frontend/components/ui/`만(CLAUDE.md 코드 컨벤션). 사이드바처럼 새로 필요한 색은 토큰을 더해 쓴다
- 다크는 지금처럼 `<html data-theme="dark">`
- 문서: `docs/치과 AX - 앱 설계.md`의 화면 절이 "색·모양은 `globals.css` 토큰과 `components/ui`에서 나온다"고 가리키므로 값은 적지 않는다. `globals.css` 머리 주석(Graphite·딥 틸)은 새 조합 이름으로 고친다

## 만드는 사람에게 맡기는 것

- 제목 띠를 만드는 방식(공용 `PageHeader` 부품 등 — AI 비서·EMR은 띠가 없다)
- Pretendard 불러오는 방식 — 단, 실행 중 외부 CDN에 기대지 않는다(지금 글꼴처럼 빌드에 들어가게)
- 사이드바 색을 토큰 몇 개로 나눌지, 이름
- 말풍선·빈 상태·표 머리처럼 새 바탕에서 어색해지는 곳의 세부 조정
- 작업 순서와 커밋 나누기
