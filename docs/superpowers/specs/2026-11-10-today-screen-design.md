# 오늘 화면 — 설계

원본 규칙은 [[치과 AX - 기능 정의]] §4 앱 구성의 "오늘 화면"·§4 ①, [[치과 AX - 앱 설계]] §3b·§4·§9, 와이어프레임 `docs/wireframe/index-v2.html`의 `R.today`. 이 문서는 그 위에서 이번 브랜치(`feat/today`)가 만들 범위와 이번에 정한 것을 적는다.

## 왜

메뉴 첫 칸 "오늘"은 지금 "준비 중"이다. 사내 포털에 들어오면 처음 보는 화면이 비어 있다. 직원은 출근해서 "오늘 무엇이 남았고 어디서 처리하나"를 통화·준비표·AI 평가 화면을 하나씩 열어 맞춰 봐야 한다. 오늘 화면은 그걸 한 장으로 모으고, 누르면 처리할 화면으로 보낸다. 또 AI가 사람 몰래 처리한 일이 없다는 걸 매일 아침 보여 주는 자리다(자동 처리 목록과 다시 열기).

## 목표

- `/today` 화면: 요약 카드 4개 → **사람이 볼 일**(넓게, 급한 것부터) → **AI가 한 일**(한 줄 요약 + 펼치기). 배치는 시안 B(사용자 결정)
- `GET /today` — 숫자는 전부 쿼리(기능 정의 §3 원칙 2). LLM 호출 없음
- **확인할 통화**: AI 할 일 줄이 없는데 사람이 일이 남았다고 표시한 통화를 띄우고, 통화 상세의 **확인함** 버튼으로 뺀다(기능 정의 §9 미결 항목을 이 방식으로 닫는다 — 사용자 결정)
- 통화 상세의 자동 종결 띠 버튼 `되돌리기` → `다시 열기`(사용자 결정)
- 기능 정의 §9 착수 순서를 고친다(아래 "문서")

## 하지 않는 것

- **⑦ 아침 브리핑**: 운영 에이전트의 밤사이 결과를 입력으로 쓰므로 운영 에이전트와 함께(사용자 결정)
- **환자로 묶은 신호**(운영 에이전트), **슬롯 칸**(재심 기한·청구 전 경고·후속 관리·일계표 불일치): 그 기능을 만들 때 각자 "사람이 볼 일"에 줄을 더한다. 이번에는 자리("준비 중")도 두지 않는다
- **역할별 보기**(원장·데스크·진료실): 모두 같은 화면(사용자 결정). 재무·청구 칸이 붙는 ⑤·⑧ 때 할 일이 많아지면 그때 필터를 본다. 경영 리포트는 오늘 화면이 아니라 리포트 메뉴
- **배치 작업 기록**("03:10 끝남"): `make classify`·`make followups`·`make prep`은 실행 기록을 남기지 않는다. 끝난 시각·끝남/실패 목록은 `make nightly` 때 `ax_jobs`와 함께. 이번에는 결과 표에서 센다(사용자 결정)
- **새로 추가한 통화의 검색 색인**(기능 정의 §9가 "오늘 화면·`make nightly` 착수 시"로 걸어 둔 항목): 화면과 상관없고 임베딩 비용이 드는 일이라 `make nightly` 때로 옮긴다(**내 판단**)
- 이 화면에서 일을 처리하기(할 일 체크·판정·준비표 갱신). 오늘 화면은 보여 주고 보내기만 한다. 예외는 자동 처리의 **다시 열기**(기능 정의 §4 "AI가 한 일"의 되돌리기)

## 하면 실패인 것

- 사람이 일이 남았다고 표시한 통화(다시 연 통화, 사람 판정이 할 일·응급·불만·급함을 켠 통화)가 오늘 화면에도 통화 화면에도 안 뜬다
- 오늘 화면의 숫자가 그 숫자가 가리키는 화면의 숫자와 다르다(예: "주의 환자 6명"을 눌렀는데 준비표 주의 칩이 5명). 같은 쿼리·같은 함수를 쓴다
- 준비표의 환자 목록을 오늘 화면에 다시 만든다(준비표와 겹치는 것은 숫자 + 이동만)
- 화면에 시스템 말·코드 값(`has_todo`, `call_autoclose`, `refused` 등)이 보인다(앱 설계 §9 "배치")
- backend가 `ground_truth/`·`generator/`·`evaluation/`을 참조한다(절대 규칙). 판정 풀(`in_eval_pool = 1`) 통화가 할 일·확인할 통화에 섞인다

## 정한 것

### 1. 화면 구성 (시안 B)

위에서 아래로. 숫자를 누르면 그 화면으로 간다.

1. **요약 카드 4개**
   - 오늘 예약 N명(진료·위생·상담 수) → 준비표
   - 신환 N명 → 준비표
   - 주의 환자 N명 → 준비표 `?chip=alert`
   - 오늘 할 일 N건 · 급함 n → 통화(오늘 할 일)
   - 예약·신환·주의는 준비표 `GET /prep`과 같은 함수(`backend/prep.py` `prep_facts`·칩)로 센다. 기준일 = 앱 기준일(`shared/clinic.py`)
2. **사람이 볼 일** — 급한 것부터, 한 줄 = 꼬리표 + 내용 + 이동
   - **급한 통화**: 응급·급함 통화 **전부**(사용자 결정 — 개수 제한 없음). 이름·용건·통화 날짜 → 그 통화 상세. 통화 화면 "오늘 할 일"(`backend/calls.py` `today_board`)과 같은 대상·같은 순서
   - **확인할 통화**: §2. 이름·이유·날짜 → 그 통화 상세
   - **예약 미확인**: 숫자만 → 준비표 `?chip=unconfirmed`
   - **주의 환자**: 숫자만 → 준비표 `?chip=alert`
   - **남은 통화 할 일**: 끝내지 않은 할 일 줄 수(통화 수) → 통화 오늘 할 일
   - **판정 대기**: 사람 판정을 기다리는 엇갈림·표본 수 → AI 평가(판정 탭). 수는 판정 큐 "다음 건"(앱 설계 §6 "판정 큐")의 대상과 같은 조건
   - **근거 없는 질문**: 물어보기에서 문서 근거를 못 찾아 거절된 질문(`ax_search_logs` `status = 'refused'`, `is_eval = 0`, 챗·검색 요약 둘 다) 중 **최근 7일**(`created_at` 실제 시계) — **있을 때만** 줄을 보인다(사용자 결정). 확인함은 두지 않는다 — 7일이 지나면 빠진다. 질문·시각 → 물어보기를 열고 **입력칸에 질문만 채운다**(바로 실행하지 않음 — 비용이 들고, 또 거절되면 줄이 하나 더 생긴다). 물어보기 화면이 주소로 질문을 받게 고친다(예: `/ask?q=…`, 이름은 빌더 판단). 문서 초안 에이전트가 생기면 "초안 작성됨"을 붙인다
   - 0건인 줄은 숨긴다(**내 판단** — 급한 통화·확인할 통화·근거 없는 질문은 확실히 숨기고, 숫자 줄은 0이어도 "0"으로 둘지 빌더 판단). 모두 0이면 "오늘 남은 일이 없습니다"
3. **AI가 한 일** — 한 줄 요약(`자동 처리 N건 · 오늘 준비표 N행 · 실패 n`) + 펼치기
   - **자동 처리**: 되돌리지 않은 `ax_auto_actions`(지금은 `call_autoclose`뿐 — 통화 화면과 같은 유효 조건: 정책이 켜져 있고 활성 버전 쌍으로 닫은 것, `backend/calls.py` `ROWS_SQL`). 요약 숫자는 **지금 닫혀 있는 통화 전부**, 펼친 목록은 **최근에 닫힌 순(`created_at`) 20건**과 "전체 보기 → 통화 기록"(사용자 결정 — 정책을 켜면 `make autoclose`가 지난 통화까지 한 번에 닫아 수백 건이 될 수 있다). 건별 통화 이름·이유(사람 말로)·시각 + **다시 열기**(기존 `POST /auto-actions/{id}/revert`). 다시 연 건은 목록에서 빠지고 "사람이 볼 일"의 확인할 통화로 간다
   - **결과 표에서 센 줄**(시각 없음):
     - 오늘 준비표 N행 · 제안 n · 후검증 실패 k → 준비표(실패 k > 0이면 "사람에게 넘김" 꼬리표)
     - 통화 분류 실패 k건(활성 분류 버전, 판정 풀 밖) → 통화(다시 분류)
     - 처리안 실패 k건(`ax_call_followups` `status = 'failed'`, 활성 분류 행) → 통화
     - 실패 0인 줄은 "끝남", 0보다 크면 "사람에게 넘김" 꼬리표(와이어프레임의 끝남 / 사람에게 넘김 / 실패 중 "실패"는 실행 기록이 있어야 해서 이번에는 쓰지 않음)
   - 자동 처리가 꺼져 있으면(`auto_policy`) 요약에 "자동 종결 꺼짐"을 적는다 — 0건이 고장이 아니라 꺼진 것임을 보인다

### 2. 확인할 통화 (사용자 결정)

**대상**: 판정 풀 밖 통화(생성 + 새로 추가한 통화) 중 **지금 통화 화면 오늘 할 일(`today_board`)에 뜨지 않는** 통화로, 아래 중 하나인 것. **날짜 제한 없음**(사용자 결정) — 사람 판정은 날짜와 상관없이 하므로(판정 대상 1,350건 중 기준일 전 7일 안은 21건), 오늘 할 일의 7일 창(`TODAY_WINDOW_DAYS`)으로 자르면 대부분 어디에도 안 뜬다. "뜨지 않는다" = AI 할 일 목록이 비었거나, 할 일은 있지만 7일 창 밖이라 빠진 통화(분류가 `ok`가 아니면 "AI가 한 일"의 분류 실패 줄이 맡는다)

- **다시 열림**: 그 통화의 `call_autoclose` 자동 처리를 사람이 되돌렸다(`reverted_at IS NOT NULL`) — 오늘 화면의 다시 열기, 통화 상세의 다시 열기, 사람 판정으로 풀린 것(`backend/autoclose.py` `unclose_by_human`) 모두
- **사람 판정이 일을 켬**: `ax_judgments.labels`가 할 일 있음·응급·불만·급함 중 하나 이상

통화 화면 오늘 할 일에 이미 뜨는 통화(7일 창 안이고 AI 할 일 목록이 있음)는 여기 넣지 않는다. 확인함을 누를 때까지 남는다. 문구의 "AI: 할 일 없음"은 AI 할 일 목록이 빈 통화에만 쓰고, 할 일이 있지만 창 밖인 통화는 `AI: 할 일 있음(지난 통화), 사람 판정: 응급`처럼 쓴다(**내 판단**)

**문구**(사용자 결정 — "AI: …, 사람…: …" 꼴로 맞춤, 줄 안의 구분은 `·`, 두 판단 사이는 쉼표):
- `확인할 통화  김○○ · AI: 종결, 사람: 다시 열림 · 11/28`
- `확인할 통화  이○○ · AI: 할 일 없음, 사람 판정: 응급 · 11/27`
- 여러 개면 `사람 판정: 응급·불만`. 항목 이름은 `GET /labels`(`shared/call_labels.py`)의 한국어 이름. "판정"만 쓰지 않는다 — 판정기(모델 B)와 헷갈린다
- 둘 다 해당하면 한 줄에 사람 판정 쪽 문구(**내 판단**)

**확인함**: 통화 상세에 버튼 하나. 누르면 그 통화가 확인할 통화에서 빠진다. 누가·언제를 남긴다(실제 시계, 다른 사람 기록과 같은 꼴). 저장 방법은 빌더 판단 — 기존 `ax_todo_checks`는 (분류 행, 할 일 번호) 키라 할 일 줄 없는 통화에 그대로 맞지 않으므로 새 앱 테이블이 자연스럽다(**내 판단**). 확인한 뒤 사람 판정이 바뀌거나 다시 닫혔다 다시 열리면 다시 뜬다(판정 시각·다시 연 시각이 확인 시각보다 뒤)

### 3. 다시 열기 (사용자 결정)

- 통화 상세 자동 종결 띠의 버튼 `되돌리기` → `다시 열기`. 오늘 화면 "AI가 한 일"의 자동 종결 건 버튼도 `다시 열기`
- 공통 개념(자동 처리 전체, 앱 설계 §3b·§9 `AutoAction`)으로서의 "되돌리기"는 그대로 둔다 — ⑧ 증빙 매칭·⑨ 자동 안내는 "다시 열기"가 아니다. 화면 버튼만 작업 종류에 맞는 말을 쓴다
- 통화 기록 목록의 `자동 종결` 배지, 할 일 체크 해제의 "되돌리기"(다른 기능)는 그대로

### 4. API

- `GET /today` — 위 1의 숫자·목록 전부를 한 번에. 앱 기준일 기준. 모양은 빌더 판단(카드·사람이 볼 일 줄·AI가 한 일 묶음). 줄마다 이동할 곳(화면 경로와 쿼리)을 서버가 정할지 화면이 정할지는 빌더 판단
- 확인함: 통화 단위 쓰기 하나(예: `POST /calls/{call_uid}/check`) — 이름은 빌더 판단
- 다시 열기: 기존 `POST /auto-actions/{id}/revert` 그대로

### 5. 테스트

- 백엔드(pytest): `GET /today`의 각 숫자가 그 화면의 숫자와 같다(준비표 칩 수 = `GET /prep` 칩 수, 남은 할 일 = `today_board`). 확인할 통화 대상 — 다시 연 통화, 사람 판정이 켠 통화(넷 각각), 7일 창 밖 통화도 포함, 오늘 할 일에 이미 뜨는 통화는 제외, 판정 풀 통화 제외, 확인함 뒤 빠짐, 확인 뒤 판정이 바뀌면 다시 뜸. 거절된 질문은 `is_eval = 0`·최근 7일만. 자동 처리 유효 조건(정책 꺼짐·옛 버전 쌍이면 목록에 없음), 목록 20건·요약은 전부
- 화면(e2e): 카드·줄을 누르면 그 화면(준비표는 칩이 걸린 채, 근거 없는 질문은 물어보기 입력칸에 질문이 채워진 채 실행 안 됨), 0건 줄은 숨김, 다시 열기 → AI가 한 일에서 빠지고 확인할 통화에 뜸, 통화 상세 확인함 → 빠짐, 통화 상세 버튼 문구 `다시 열기`
- e2e는 복사본 `app.sqlite`에 쓰므로 실데이터를 더럽히지 않는다(`frontend/playwright.config.ts`). 지금 실데이터는 자동 처리·사람 판정·거절 질문이 0건이라, 그 경우는 `page.route` 가짜 응답이나 테스트 안에서 만든 행으로 고정한다

### 6. 문서

- 기능 정의 §9 착수 순서 → 오늘 화면(⑦ 빼고) → ⑨ 후속 관리 → ⑤ 청구 점검 → ⑧ 재무 대조 → ⑥ 경영 리포트 → ⑦ 아침 브리핑 + 운영 에이전트. ⑧을 ⑥ 앞에 두는 근거: ⑥ 월간 재료비·기공비가 ⑧-2 확정 계정을 쓴다(기능 정의 §4 ⑥)
