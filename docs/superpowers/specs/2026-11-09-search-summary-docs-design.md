# ③ 기록 검색 요약·문서함 설계 — 브랜치 2 `feat/search-summary-docs`

원본: `docs/치과 AX - 기능 정의.md` §4 ③(화면·API), `docs/치과 AX - 앱 설계.md` §2(`ax_llm_calls`)·§3(검색·`ax_search_logs`·인용 확인)·§9(`/ask`), 앞 설계 `docs/superpowers/specs/2026-11-09-chat-agent-design.md`(브랜치 1 — 숫자 후검증·상태·고정 문구), 와이어프레임 `docs/wireframe/index-v2.html` `askSearch`·`askDocs`. 이 문서는 브랜치 2에서 새로 정한 것만 적는다.

## 왜

기록 검색은 결과 카드가 20장까지 나와 직원이 다 읽기 어렵다. 그래서 카드가 무엇을 말하는지 몇 줄로 묶어 보여 주고, 정확한 답이 필요하면 질문하기로 한 번에 넘어가게 한다. 문서함은 검색 없이 문서 전체를 읽는 곳이다. 문서는 약 80개이고(최신 공지 12·매뉴얼 34·FAQ 13·보험 안내 7·청구 기준 5·교육 5·외부 5), 한 줄로 늘어놓으면 아래쪽 종류까지 스크롤해야 해서 종류별로 나눠 보인다.

## 목표·안 하는 것

- **목표**: 기록 검색 AI 요약, "이걸로 질문하기"·"근거 더 보기" 연결, 문서함(`GET /documents`·`/documents/{id}`·탭)
- **안 하는 것**: 요약이 검색어에 답하기(답은 질문하기 몫), 요약 평가 지표·`eval.py` 채점, 문서함 제목 찾기 칸(내용 검색은 기록 검색 몫), 문서 편집·초안 목록(브랜치 3 `feat/doc-draft`), 요약 스트리밍
- **실패로 볼 것**: 검색 결과 밖 청크를 인용하거나 결과에 없는 숫자가 든 요약이 화면에 나가는 것, 옛 공지의 값을 현재 값처럼 요약하는 것, 요약을 기다리느라 검색 결과가 늦게 뜨는 것, 같은 검색을 다시 열 때마다 요약 호출이 다시 나가는 것

## 사람이 정함

- **요약은 자동**: 검색할 때마다 만든다. 결과가 먼저 뜨고 요약은 따로 채운다. 결과가 0건이면 부르지 않는다. 같은 검색을 다시 열면(새로고침·뒤로 가기) 저장된 요약을 다시 쓴다
- **요약 내용은 "찾은 결과가 무엇을 말하는지" 정리**: 문장마다 끝에 출처 번호(`[1]`, `[1][3]`)를 붙이고, 아래 출처 칩에 같은 번호를 단다 — 직원이 문장 하나를 확인하려고 출처를 다 열지 않게. 검색어에 답하지 않고, 결과를 세어 건수나 결론을 내지 않는다(결과는 상위 일부라 건수가 틀린다). 정확한 답은 "이걸로 질문하기"로 넘긴다
- **문서함은 종류 칩**: 목록 위에 종류 칩 7개를 문서 수와 함께 두고, 고른 종류만 목록에 보인다. 처음에는 공지가 선택돼 있다. 공지는 최신 버전만 보이고 시행일이 붙으며, 본문 아래에 옛 버전 링크가 있다. 읽기 전용이다. 제목 찾기 칸은 두지 않는다. 와이어프레임 `askDocs`에 반영해 두었다
- **문서로 이어 주기**: 기록 검색 결과의 문서 카드와 질문하기 답의 문서 출처에서 문서함의 그 문서를 연다. 열 때 그 문서 종류의 칩이 선택된다

## 내가 정함 (검토 바람)

### 요약 API

- **`POST /search/summary`**: 본문은 `GET /search`와 같은 인자(`q`, `source_types`, `date_from`, `date_to`, `chart_no` — `to_search_args`를 같이 쓴다). 응답은 `{status, text, sources[]}`이고, `sources`는 `cited_ids`를 검색 카드 형식(`backend/search_cards.py` `card`)으로 바꾼 것이다. 스트리밍하지 않고 JSON 한 번으로 돌려준다(호출이 하나뿐이다)
- **서버가 검색을 다시 한다**: 화면이 결과 id를 넘기지 않는다. 그러면 인용 확인의 기준(`retrieved_ids`)이 서버 안에서 정해진다. Voyage 호출은 두 번이 되지만 비용은 무시할 만하다. Voyage 사용량은 `/search`처럼 `record_voyage`로 남긴다
- **다시 쓰기(캐시)**: `ax_search_logs`에서 `kind='search_summary'`, `is_eval=0`, `status IN ('answered','refused')`인 행 가운데 `tool_calls`(정규화한 검색 인자 + 프롬프트 버전)와 `retrieved_ids`가 이번 검색과 같은 행이 있으면, 모델을 부르지 않고 그 행을 돌려준다. 색인을 다시 만들어 결과가 바뀌면 `retrieved_ids`가 달라지고, 프롬프트 버전을 올리면 `tool_calls`가 달라져서 새로 만든다. 모델 교체(`chat` 별칭)는 키에 넣지 않는다(드물다). 실패한 행은 다시 쓰지 않는다
- **모듈** `backend/search_summary.py` — `summarize(conn, gw, searcher, args: SearchArgs, *, is_eval=False) -> dict`. 하네스(에이전트 루프)를 쓰지 않고 게이트웨이 `complete` 한 번으로 끝낸다(`backend/chat.py` `baseline`과 같은 모양). 별칭은 `chat`, 작업 이름(task)은 `search_summary`, 프롬프트는 `prompts/search_summary/v1.md`, 출력 스키마는 `{text, cited_ids[], refused}`

### 요약 입력과 검사

- **입력**: 이번 검색의 두 버킷 결과 전부(최대 `SEARCH_TOP_K` × 2). 단 **옛 공지 청크는 빼고**(`searcher.replaced_by`에 있는 문서), 차트 청크는 챗처럼 괄호 없는 원문으로 바꿔 넣는다(`chat._chart_plain` — 공용 자리로 옮겨 같이 쓴다). 옛 공지는 결과 목록에는 "옛 버전" 딱지와 함께 그대로 보인다. 옛 공지를 빼고 입력이 비면 모델을 부르지 않고 행도 남기지 않으며, 화면에는 `refused` 문구를 낸다. 외부 텍스트는 `external()`로 감싼다
- **출처 번호 형식**: 모델은 `text` 문장 끝에 `[n]`을 붙이고, `[n]`은 `cited_ids[n-1]`을 가리킨다. 화면 출처 칩은 `cited_ids` 순서대로 1부터 번호를 단다
- **검사**(숫자는 챗과 같은 함수 — `backend/verify.py`)
  1. 인용: `cited_ids` ⊆ 입력 청크 id, 본문의 모든 `[n]`이 1..`len(cited_ids)` 안, `cited_ids`가 모두 본문에서 한 번 이상 쓰임. `refused`가 아니면 `cited_ids`는 비면 안 된다
  2. 문장 끝 번호: 본문을 문장으로 나눠(`.`·`?`·`!`·줄바꿈 기준, 숫자 뒤·마침표 뒤 마침표에서는 나누지 않음) 끝에 번호가 없는 문장이 있으면 막는다
  3. 숫자 후검증: `[n]` 표지를 뗀 본문의 숫자가 모두 검색어·필터 값(기간·환자번호)과 입력 청크 본문에 있다(표지 숫자를 근거 없는 숫자로 세지 않게). 행 수 허용(`count_rows`)은 켜지 않는다 — 요약은 결과를 세지 않는다
  4. 어긋나면 이유를 붙여 한 번 다시 부른다(챗과 같은 한 번 재시도). 두 번째도 어긋나면 고정 문구로 끝내고 `cited_ids`를 비운다
  5. 막힐 때마다 `ax_rule_counts`에 더한다 — `search_summary.cite_outside`(1), `search_summary.cite_missing`(2), `search_summary.number_unverified`(3). 1·2는 상태 `cite_failed`, 3은 `number_failed`
- **상태**(`ax_search_logs.status`, 칸은 그대로): `answered` / `refused`(모델이 정리할 내용이 없다고 함 — 벡터 검색에 임계값이 없어 관련 없는 결과가 올 수 있다) / `cite_failed` / `number_failed` / `budget`(하루 상한 `BudgetExceeded`) / `failed`(게이트웨이 실패). 실행 중 행(`running`)은 만들지 않고 끝난 뒤 한 번 쓴다. 화면 문구: `refused`는 "검색 결과에서 정리할 내용을 찾지 못했습니다", 나머지 실패는 "요약을 만들지 못했습니다"(문구 상수는 `backend/search_summary.py`)
- **기록**: `ax_search_logs` 1행 — `question`=검색어, `tool_calls`=`[{name: "search", args: 정규화 인자, prompt_version}]`, `retrieved_ids`=입력 청크 id, `run_id` 없음, `fallback_used`. `ax_llm_calls`는 `ref` 없이 남긴다(기준선과 같다 — 앱 설계 §2 "`ref_type`은 `agent_run`만")
- **비용**: 요약 한 번에 Sonnet 1~2회. 결과 20장 기준으로 회당 약 $0.03이라고 추정한다(구현 때 실측해 실험 기록에 적는다). 하루 상한 안에서 센다

### 문서함 API

- **`GET /documents`** → `{documents: [{id, type, title, version, effective_date}]}`. 공지는 같은 제목의 최신 버전만 낸다. "최신"은 `Searcher._replacements`와 같은 규칙(시행일 내림차순, 같으면 id 큰 것)이고, 함수 하나로 모아 둘이 같이 쓴다. `source.sqlite`만 읽는다(`_open_source` — 색인 없이도 열린다)
- **`GET /documents/{id}`** → `{id, type, title, version, effective_date, body, versions: [{id, version, effective_date}], latest_id}`. `versions`는 같은 제목 공지의 모든 버전이고 최신이 먼저다(공지가 아니면 빈 목록). 없는 id는 404
- 게시된 문서 초안을 합치는 것은 브랜치 3에서 한다

### 화면 (`/ask`)

- **기록 검색**: 검색 폼 아래, 결과 위에 AI 요약 카드를 둔다(와이어프레임 순서). 결과가 오면 화면이 `POST /search/summary`를 부른다. 결과가 0건이거나 오류면 부르지 않는다. 카드 상태는 만드는 중 / 요약 + 출처 / `refused` 문구 / 실패 문구다. 본문의 `[n]`은 작은 번호 표지로 그리고, 출처는 같은 번호를 단 짧은 칩(번호·종류·제목, 또는 번호·날짜·차트 번호)으로 보인다. 문서 칩은 문서함을 연다. 카드 아래에 "이걸로 질문하기" 버튼이 있고, 요약이 실패해도 보인다. 요약 카드는 AI가 만든 칸 표시를 따른다
- **이걸로 질문하기**: 질문하기 탭으로 바꾸고 검색어를 입력칸에 넣는다. 바로 보내지 않는다 — 검색어는 질문이 아니라 조건인 경우가 많아 직원이 고쳐 쓰게 한다
- **근거 더 보기**: 질문하기 답 카드마다(거절·실패 포함) 둔다. 그 질문으로 기록 검색을 연다(`/ask?tab=search&q=…`)
- **문서함**: `/ask?tab=docs&doc=<id>` — 상태는 기록 검색처럼 URL에 둔다. 종류 칩은 `?doc`이 가리키는 문서의 종류를 따르고, 없으면 공지를 고른다. 칩을 바꾸면 그 종류의 첫 문서를 연다. 옛 버전 공지를 열면 본문 위에 "옛 버전 — 최신 v○ 보기" 줄을 둔다
- **문서 카드에서 열기**: 검색 결과 카드는 지금 본문 펼치기 버튼이 있어서 카드 전체를 링크로 만들지 않고, 문서 카드에 "문서함에서 보기" 링크를 더한다. 질문하기 출처 카드도 같은 카드 부품을 쓰니 함께 된다
- **본문 렌더링**: 문서 본문은 마크다운이다(표가 있는 문서 6개, 굵게가 있는 문서 25개). `react-markdown` + `remark-gfm`을 더한다. 원시 HTML은 그리지 않는다(기본값). 스타일은 `globals.css` 토큰만 쓴다
- **종류 이름**: `result-card.tsx` `DOC_TYPE`을 `frontend/lib/`로 옮겨 칩과 카드가 같이 쓴다

### 테스트

- 백엔드(pytest, 가짜 게이트웨이 — `tests/backend/script.py`): 인용 밖·번호 범위 밖·번호 없는 문장·쓰이지 않은 출처·근거 없는 숫자(표지 숫자는 통과) → 한 번 재시도 → 고정 문구와 상태, 옛 공지가 입력에서 빠지는지, 캐시 재사용(같은 인자·같은 결과·같은 프롬프트 버전이면 게이트웨이를 부르지 않음, 하나라도 다르면 새로 만듦), 0건이면 부르지 않음, `GET /documents` 최신 공지만, `/documents/{id}` 버전 목록·404
- 화면: `make e2e`에 문서함 칩 전환, 검색 결과 → 문서함 열기, 이걸로 질문하기·근거 더 보기 이동을 더한다(실데이터 복사본이고, 요약 호출은 과금이라 e2e는 요약 응답을 가로채 가짜로 준다)
