# 청구 기준 문서 — 실제 고시 발췌로 바꾸기 (A안)

## 왜

⑤ 청구 점검이 읽는 청구 기준 문서 5개(`generator/doc_catalog.py` `CLAIM_DOCS`)는 가상이다. 실제 고시 원문과
견줘 보니 11개 사유 중 8개는 원문에 대응 문장이 있다. 나머지 3개(R01~R03)는 실제 고시에 같은 뜻의 문장이 없다. 실제
고시는 "기간 안 재시술은 50% 산정" 같은 산정 규칙이고, 차트 기록 요건이 아니기 때문이다.

목표는 "실제 원문이 받치는 절은 실제 원문 그대로, 나머지는 병원 내부 점검 기준이라고 표시"해서 포트폴리오에서
범위를 정확히 말할 수 있게 하는 것이다. 조정 건수·오류의 구성은 바꾸지 않는다. 기준일 기준 재심 기한이 남은 101건
중 57건이 실제 원문 기준 사유가 된다.

## 절별 본문

모든 청구 기준 문서 머리말에 한 문장을 더한다: "이 문서의 절은 실제 고시 발췌(출처 표기)와 병원 내부 점검 기준(표시)으로
나뉜다."

실제 절의 모양은 아래와 같다.

```
## <절 제목>

> <원문 인용 — 줄마다 '> '>

출처: <출처 줄>

병원 내부 보충: <보충 문장>      ← 있을 때만
```

가상 절의 모양: `## <절 제목>` 다음 첫 줄에 "병원 내부 점검 기준 — 고시에 같은 문장 없음", 그 아래는 지금 LLM 본문을
그대로 둔다.

생략은 "…"로 표시한다. 절 제목 11개(`CLAIM_HEADINGS`), 문서 5개의 분야 묶음, 문서 번호는 바꾸지 않는다.

## 문서 본문을 코드가 쓴다

- `claim_standard` 5개는 9단계 LLM(`generator/documents.py` `TASK`)을 거치지 않는다. 계획 단계(`stage_plan`)가
  위 본문을 그대로 넣는다. 다른 문서는 지금처럼 LLM이 쓴다.
- verify `check_claim_sections`(사유마다 절 1개, 기준 말이 절 안)는 그대로 통과해야 한다.
  - 각 절의 "꼭 넣을 말"(`Fact.words`)은 그 절 본문에서 고른다(예: R05 "X-선 촬영", R06 "부분 무치악", D03 "치식").
- 테스트: 실제 절 인용 블록이 저장소의 원문 상수와 글자까지 같은지 본다(옮겨 적다 글자가 바뀌지 않게).

## 사랑니 차트(R05) 근거 모양

실제 기준의 근거는 X-선 촬영 확인이다. 지금 사랑니 차트 195건에는 X-선 언급이 0건이다. 그래서 R05 요건 줄의 차트
서술만 다시 만든다. 어느 줄이 오류인지(`truth_claim_errors`)는 바꾸지 않는다.

- **근거 있음**: 촬영(파노라마·치근단 X-선)으로 매복 상태를 확인했다는 서술 + 매복 정도 + 골삭제.
- **근거 없음**:
  - 촬영 언급이 없다.
  - 일부(새 상수, 값은 `PERIO_NEAR_MISS_SHARE`와 같은 0.33, 추정값)는 매복 정도·골삭제는 적혔는데 촬영이 없는
    부분 소견으로 만든다. R03의 깊지만 출혈 없는 소견처럼, AI가 실제로 읽는지 보는 모양이다.
  - 부정(`EVIDENCE_NEGATED_SHARE`)은 촬영을 부정하는 문장으로 바꾼다(`NEGATION["R05"]`).
- **바꿔 말하기**(`EVIDENCE_PARAPHRASE_SHARE`): 촬영 말의 다른 표현을 `PARAPHRASE`에 더한다.
- **근거 말**: `EVIDENCE_WORDS["R05"]`는 촬영 말이 된다. 키워드 기준선(`evaluation/claim_check.py`
  `keyword_rule`)도 같은 표를 쓴다. 근거 없는 줄의 금지 말(`evidence_forbidden`)도 촬영 말이므로, 부분 소견 줄에는
  매복·골삭제가 남아도 된다. 키워드 기준선은 부정·바꿔 말하기에서 속고, 부분 소견에서는 맞힌다(공정한 기준선).
- verify 검사를 먼저 고친다(TDD).
- 차트는 `/fill-llm-jobs`로 채운다(API 과금 없음). 정답을 숨긴 판독(보조 에이전트)으로 "읽으면 풀리는지" 표본을
  확인한다(AI 실험 기록 §24와 같은 방식).

조정 건을 펼친 곳의 절 카드(`frontend/components/claims/` — 지금 `whitespace-pre-line` 평문)를 문서함과 같은
마크다운 렌더링(`frontend/components/ask/doc-body.tsx`)으로 그린다. 그래야 인용 블록과 출처 줄이 제대로 보인다.

"실제 고시 / 병원 내부 기준" 딱지는 붙이지 않는다. 출처 줄과 가상 절 첫 줄의 표시가 그 구분을 한다. 청구 기준 찾기
결과가 같은 카드를 쓰면 함께 바뀐다. e2e로 확인한다.

## 데이터 상태

데이터는 고정이다. 이번에 재설계로 여는 범위는 둘뿐이다.

1. 9단계 청구 기준 문서 5개
2. 9b 차트 서술 중 R05 요건 줄

`emr_*` 정형 행·`fin_*`·정답 테이블은 바꾸지 않는다. 끝나면 `make data` → `make verify`로 다시 고정한다. ③ 질문
평가셋(`rag_qa.json`)은 청구 기준 문서를 정답으로 쓰지 않아 영향이 없다.

## 문서 반영

- 기능 정의 §9
  - "실제 청구 기준" 항목: 끝낸 것을 지우고, 남은 것(R01~R03을 실제 산정 규칙 모양으로 — B안)만 남긴다.
  - 새 할 일: ⑤-4 사유서가 출처 없는 절(병원 내부 기준)을 "기준 절 인용"으로 쓰지 않게 하기(프롬프트 개정 때).
- 가상 데이터 생성 설계: 청구 기준 문서 규칙(코드가 쓰는 본문, 실제 절·가상 절·보충 줄·출처 줄).
- 앱 설계: 절 카드 마크다운 렌더링.
- AI 실험 기록: 새 절. 바뀐 문서로 다시 잰 ⑤ 수치를 이전 수치와 나란히 적고, 원문 없는 사유와 `cq-R04-1`을 한계로
  적는다.
- 데이터의 알려진 흠: 실란트 나이(병원 12세 / 실제 18세), 급여 임플란트 2개 초과 환자, 청구방법 고시 출처 판(2016
  전체본 문구).

## 하지 않는 것

- R01~R03을 실제 산정 규칙 모양으로 다시 설계하기(B안)
- 실제 원문 기준 사유의 조정 비율 늘리기(청구 단계가 바뀌어 ⑧ 재무 데이터까지 흔들림)
- 시술 표에 없는 고시 항목(진찰료, 방사선 촬영료, 마취, 틀니 등) 넣기
- 프롬프트 개정(⑤-4 출처 없는 절 인용 포함)
- "실제 고시 / 병원 내부 기준" 화면 딱지
