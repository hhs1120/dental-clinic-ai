# 랭그래프 비교 실험 설계 — ⑧-1 불일치 조사 에이전트

근거: [[치과 AX - 기능 정의]] §9 "랭그래프 비교 실험", [[치과 AX - 앱 설계]] §3b(하네스를 직접 구현한 이유), [[치과 AX - AI 실험 기록]] §26(⑧-1 v3 dev 결과).

## 1. 왜

앱 설계는 랭체인·랭그래프를 쓰지 않고 하네스를 직접 만든 이유를 이렇게 적었다: 프레임워크가 덜어 주는 것은 도구 루프와 재개 정도이고, 권한·훅·자동 처리·저장소 주입은 어차피 코드로 강제해야 하며, 체크포인트를 따로 두면 상태가 `ax_agent_steps`와 둘로 갈라진다.

이 실험은 그 주장을 실제로 잰다. 같은 에이전트를 랭그래프로 한 번 더 만들어 같은 입력으로 나란히 돌리고, 결과·호출 수·비용·재개 동작·코드 양을 비교한다. 포트폴리오에서 말하는 것: "두 도구를 다 써 봤고, 이 앱에서 직접 만든 쪽을 고른 근거가 숫자로 있다." 랭그래프가 이기는 항목이 있으면 그대로 적는다.

## 2. 대상과 범위

- **대상**: ⑧-1 불일치 조사 에이전트(`backend/recon_agent.py`, 프롬프트 v3). 단계가 많고(평균 6.1, 최대 12), 근거 번호 훅·비용 상한·재개·조사 과정 화면 줄이 있어 위 주장을 가장 세게 시험한다.
- **앱은 바꾸지 않는다**: 랭그래프판은 실험 모듈로만 있고 앱·nightly·화면은 지금 하네스를 그대로 쓴다. `backend/`는 이 모듈을 import하지 않는다.
- **같게 두는 것**(차이가 프레임워크에서만 나오게): 프롬프트 v3, 도구(`backend/recon_tools.py` 조회 도구 + `submit_cause`), 입력 글(`recon_tools.input_text`), 모델 별칭 `recon`과 게이트웨이(`shared/llm.py` — 모든 LLM 호출은 게이트웨이를 지난다, 랭체인 모델 클래스는 쓰지 않는다), 상한(`RECON_MAX_TOOL_CALLS` 12, `RECON_MAX_USD` 0.3), 근거 번호 규칙(`recon_agent._evidence`), 외부 데이터 감싸기(`backend/harness/loop.py` `external`·`TRUST_NOTICE`).
- **넣지 않는 것**: ⑧-2·다른 에이전트, 자동 마감 연결, 화면.

## 3. 랭그래프판

- **모듈**: `evaluation/langgraph_recon.py`. 의존성은 새 uv 그룹 `langgraph`(`langgraph`, `langgraph-checkpoint-sqlite`) — 기본 그룹에 넣지 않는다(`finetune`과 같은 방식).
- **그래프**: 상태 = 대화 메시지·조회 기록·호출 수·비용. 노드 `model`(게이트웨이 호출) → 조건 분기(도구 호출 있음 / 끝내는 도구 / 상한 넘음) → 노드 `tools`(훅 검사 → 도구 실행 → 결과를 `external`로 감싸 붙임) → `model`로. 상한을 넘으면 사람에게 넘김(handed_off), `submit_cause`가 통과하면 끝.
- **훅**: 근거 번호 규칙은 `tools` 노드 안에서 같은 함수로 막는다(막히면 모델에 이유를 돌려준다 — 하네스와 같은 동작). 랭그래프에서 훅을 어디에 두는지가 비교 항목이다.
- **상태 저장**: 랭그래프 체크포인터(SQLite)를 `evaluation/runs/langgraph_recon.sqlite`에, thread id = 건 키. 결과 한 줄씩 `evaluation/langgraph_recon_runs.jsonl`(건 키·원인 1·2순위·근거·상태·모델 호출 수·도구 호출 수·토큰·비용). 앱 DB(`app.sqlite`)는 읽기만(조회 도구가 읽는다) — 쓰지 않는다.
- **이어 돌기**: 결과 줄이 있는 건은 건너뛴다. 끊긴 건은 체크포인트에서 이어 간다.

### 3.1 정한 것(Claude 판단)

- **저장소 어댑터**: 조회 도구(`recon_tools.tools` — 조회 번호를 `ctx.store.steps`로 센다)·근거 규칙(`_evidence`)·화면 줄(`lines`)이 하네스 저장소 모양에 기댄다. `backend/`는 고치지 않고, 그래프 상태를 `RunStore`처럼 보이게 하는 작은 어댑터를 실험 모듈에 둔다. 이 어댑터가 필요했다는 것 자체가 §4-5(상태가 갈라지는가)의 증거이므로 그대로 적는다
- **랭그래프 쓰는 정도**: `StateGraph`·조건 분기·체크포인터는 랭그래프 것을 쓴다. 메시지는 게이트웨이가 주고받는 Anthropic 형식 dict 그대로 두고 `langchain_core` 메시지·`ToolNode`는 쓰지 않는다(게이트웨이를 지나야 하므로 — 맞추려면 변환 계층이 더 필요하다). 도구 노드는 흔히 쓰는 방식(한 턴의 도구 호출을 노드 하나에서)으로 두고, 재개 시험 결과가 "노드 안에서 끊기면 그 노드를 다시 돈다"로 나오면 그대로 적는다
- **하네스 동작은 모두 옮긴다**: §2 목록 밖의 하네스 동작 — 글로 끝내면 한 번 되돌리기(nudge), 도구 결과 `DEFAULT_RESULT_LIMIT` 자르기, 인자 검증 실패·허용 밖 도구를 막힘으로 돌려주기, 도구 오류 돌려주기, 읽기 전용 도구의 DB 변경 검사, 하루 비용 상한(`BudgetExceeded`)·호출 전 비용 상한 검사 → handed_off. 빼면 모델이 다르게 움직여 비교가 깨진다. 옮긴 동작은 §4-6 "손으로 짠 것" 목록에 넣는다
- **게이트웨이 기록**: `JsonlLog`(`evaluation/langgraph_recon_llm.jsonl`) — app.sqlite에 쓰지 않는다
- **재개 시험의 CI**: 시험은 `tests/evaluation/`에 두고 `pytest.importorskip("langgraph")`로 CI(기본 그룹만 설치)에서는 건너뛴다. 로컬에서 `uv run --group langgraph pytest …`로 돌리고 결과를 실험 기록에 적는다

## 4. 비교 항목

같은 dev 불일치 건(정답 73개)에서 지금 하네스 v3 결과(앱 DB에 이미 있음, §26: 70/73, 조사 단계 평균 6.1, $3.33 Batch)와 나란히:

1. **결과**: 원인 정확도(전체·애매한 원인·규칙으로 되는 원인) — `evaluation/recon.py`와 같은 정답 대응·채점 규칙. 기권(unknown)·결과 없음 수
2. **호출**: 모델 호출 수, 도구 호출 수(조사 단계) 평균·최대, 입력·출력 토큰
3. **비용**: 실제 비용. 하네스는 라운드 배치(Batch, 단가 절반)라 직접 비교가 어려워 토큰 기준 일반 호출 환산 비용도 함께 적는다. 배치를 못 쓰는 것 자체가 비교 결과다
4. **재개**: pytest로 — 도구 호출 k번째에서 예외로 끊고 다시 돌렸을 때 (a) 끝난 모델·도구 호출을 다시 하지 않는지 (b) 비용 합이 끊지 않은 실행과 같은지. 하네스는 같은 시험이 이미 있다(`ax_agent_steps` 재구성) — 두 쪽 시험 모양을 나란히 적는다
5. **상태가 갈라지는가**: 랭그래프판 실행에서 조사 과정 화면 줄(`recon_agent.lines`)을 만들 수 있는지 — 체크포인트만으로 되는지, `ax_agent_steps`에 따로 써야 하는지. 코드로 확인하고 글로 적는다
6. **코드 양**: 랭그래프판 모듈 줄 수 vs 하네스 공용 코드(`backend/harness/loop.py` 등)와 `recon_agent.py` 중 같은 일을 하는 부분. 숫자보다 "무엇을 프레임워크가 대신했고 무엇을 여전히 손으로 짰나" 목록이 본체

## 5. 실행

- `uv run --env-file .env --group langgraph python -m evaluation.langgraph_recon run [--limit N] [--plan]` — 과금, 이어 돎. `--plan`은 대상 건 수와 하네스 실측 기준 예상 비용(무료). 훅 과금 목록에 등록
- `... score` — 무료, 위 비교표를 출력
- **범위(사용자 결정 가)**: 랭그래프판만 dev 전부(하네스 v3 실행과 같은 키 76건 — 정답 73개). 하네스는 다시 돌리지 않고 앱 DB의 v3 결과와 비교한다. 정확도는 한 번 실행이라 몇 건 차이는 실행 간 흔들림과 구분하지 못한다고 한계에 적는다
- dev만 돈다(test는 ⑧ 버전을 정한 뒤 사람이 하네스로 채점하는 몫이라 이 실험에 쓰지 않는다)
- Makefile 대상은 만들지 않는다(한 번 하는 실험이라 — Claude 판단)
