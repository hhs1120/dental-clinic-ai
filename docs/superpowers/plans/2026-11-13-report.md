# ⑥ 경영 리포트 1·2단계 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 월간·주간·일간 운영 숫자 화면 `/report`와, 이전 기간 대비 변화 분해에서 주목할 점 0~3개를 고르는 AI 해석(후검증·저장·채점)을 만든다.

**Architecture:** `backend/report.py`가 기간·숫자·변화 분해(`metrics`)·후검증·일괄 생성(`build`)·화면 응답(`sheet`)을 맡는다(④ `backend/prep.py`와 같은 틀). 재료비 과목은 `backend/expense.py` `sheet`의 줄 과목을 그대로 쓴다. 해석은 `ax_reports`에 만든 때의 `metrics`와 함께 저장하고, 지금 숫자와 해시가 다르면 `stale`로 낸다.

**Tech Stack:** Python 3 + sqlite3(SQL 그대로) · FastAPI · LLM 게이트웨이(`backend/harness/llm.py` `make_gateway`, 별칭 `chat`) · Next.js(Tailwind + shadcn/ui) · Playwright

**Spec:** `docs/superpowers/specs/2026-11-13-report-design.md`

## Global Constraints

- 앱 기준일은 `shared/clinic.py` `load_clinic().today`. 기간은 기준일 전에 끝난 것만 — 월간 6개, 주간 8개(월요일 시작), 일간 10개(취소 뺀 예약이 있는 날).
- `backend/`는 `ground_truth/`·`generator/`·`evaluation/`를 import하지 않는다. master 값은 `source.ax_master_values`로 읽는다.
- `metrics`는 평평한 dict, 값은 모두 정수. 추정 키는 `est.` 를 포함한다(`est.labor`·`est.profit`·`est.bep`, 이전 기간·증감 키도 `est.`가 들어감) — 판별은 `is_est(key) = "est." in key`.
- 인건비 기본값 `LABOR_DEFAULT = {"hygienist": 3_800_000, "desk": 3_000_000, "consultant": 3_800_000}`, `ax_settings` `labor_cost_assumed`(역할 → 원)가 있으면 역할별로 덮어쓴다. `doctor`는 넣지 않는다.
- 추정 값을 쓴 해석 점에는 `[추정]`과 `대표 원장 보수·세금 전`이 글자 그대로 있다.
- 과금 명령(`make report`)은 사용자 승인 후에만. `--split test`는 해당 없음.
- 커밋은 `<영역>: <무엇>` + 본문 글머리, `git add`는 파일 이름으로. 커밋 전 `make fmt` → `make lint` → `make test`.
- 주석·독스트링은 한국어, 근거 문서 절을 가리킨다(이 계획의 근거는 설계 `2026-11-13-report-design.md`).
- 화면 색·모서리는 `globals.css` 토큰, 부품은 `components/ui/`만.

## Review Focus

1. 데이터가 없는 기간(출금이 없는 달, 예약이 없는 주, 이전 기간 매출 0) — 0으로 채우고 증감률 키를 빼며 예외 없이 계산(Task 1 `test_empty_prev_period`).
2. 해석 이후 ⑧ 확정으로 재료비가 바뀜 — 옛 해석이 `stale: true`로 남고 `build`가 그 기간을 다시 부름(Task 3 `test_build_regenerates_stale`, Task 4 `test_sheet_stale`).
3. 다시 만들기가 두 번 실패 — 옛 해석을 지금 숫자의 해석인 척 남기지 않는다: `points` NULL·`valid` 0으로 덮어쓰고 화면은 "해석 없음"(Task 3 `test_build_fail_saves_invalid`).
4. AI 문장의 "1억 2천만 원" 같은 억 단위 — `prep.numbers`가 펴지 못해 실패로 처리(통과시키지 않는다), 프롬프트가 만 원 단위를 쓰라고 요구(Task 2 `test_check_rejects_eok`).
5. 모르는 scope·period를 API에 보냄 — 400(Task 4 `test_api_report_bad_period`).

**Files:**

**Interfaces:**
- Produces:

  - `LABOR_DEFAULT: dict[str, int]`, `MATERIAL, LAB = "재료비", "외주가공비"`

  - `prev_period(conn, today, scope, label) -> str` — 월간 앞 달, 주간 7일 전 월요일, 일간 그 전 진료일(목록 밖이어도)
  - `metrics(conn, today: date, scope: str, label: str) -> dict[str, int]`
  - `is_est(key: str) -> bool`
  - `labor(conn) -> dict` — `{"wage": {role: 원}, "headcount": {role: 명}}`
  - `dx_top(conn, month: str) -> dict | None` — `{"name": "시술 × 상병", "n": 건, "lost": 원}`, 금액(lost) 큰 순, 같으면 건수, 같으면 이름

`metrics` 키(현재 기간 값 = 기본 키):
- 공통: `sales`, `sales.<category>`(`emr_procedures.category`마다, 0이어도), `collected`, `patient_paid`, `insurer_paid`, `claimed`(그 기간 `submitted_at` 청구액 합), `visits`(취소 뺀 예약), `noshow`, `noshow_rate`(정수 %, `round(noshow*100/visits)`, visits 0이면 0), `new_patients`, `treatment_days`(취소 뺀 예약이 있는 날 수)
- 월간만: `material`, `lab`, `material_unconfirmed`(과목이 재료비·외주가공비이고 확정·자동 확정 안 된 줄 수), `account_none`, `account_none_amount`(과목이 None인 줄), `outflow`(그 달 출금 합), `profit_ex_labor`(collected − outflow), `dx_errors`, `dx_lost`(통보 월 기준, `adjust_note_types` 값이 `diagnosis`인 조정, 못 받은 금액 = claim_amount − paid_amount), `est.labor`, `est.profit`(profit_ex_labor − est.labor), `est.bep`(고정비 ÷ (1 − (material+lab) ÷ sales), 고정비 = outflow − material − lab + est.labor, 반올림. sales 0이거나 비율 ≥ 1이면 키를 뺀다)
- 기본 키마다 `prev.<key>`(이전 기간 값), `diff.<key>`(현재 − 이전), `pct.<key>`(정수 %, `round(diff*100/prev)`, prev 0이면 키를 뺀다). `noshow_rate`는 `pct.`를 만들지 않는다(%p라 `diff.`만).
