> 가상 데이터로 개발하므로 외부 LLM API를 자유롭게 쓴다. 인프라·하드웨어·운영 비용은 범위 밖.
> 이 문서는 **무엇을 만드나**. 데이터 구조와 생성 규칙은 [[치과 AX - 가상 데이터 생성 설계]], 앱 테이블·도구·쿼리는 [[치과 AX - 앱 설계]], 지표·채점·정답 저장소는 [[치과 AX - 평가 설계]], 구현 규칙은 `CLAUDE.md`.

## 1. 조건

- 기간: 준비(문서·데이터셋 생성·평가셋·환경) → 개발 3~4주
- 인원: 1인 기준. 팀이 되면 슬롯을 사람별로 배분
- 목표: "AI 도구를 잘 다루는 개발자" 포트폴리오. 풀스택 직접 구현, 프론트를 일부러 줄이지 않음
- 스택: **Next.js + TypeScript** / **FastAPI** / **SQLite**(FTS5) + **Chroma**(벡터) / 외부 LLM API를 게이트웨이 모듈 하나로 / Claude Code(`CLAUDE.md`·서브에이전트·스킬을 깃에 포함)

## 2. 범위

| 구분 | 기능 | 한 줄 |
|---|---|---|
| 코어 | 가상 데이터 생성기 | 모든 기능의 토대. 정답 내장 |
| 코어 | ① 통화 요약·분류 | 모델 2개 교차검증. 파이프라인의 뼈대 |
| 코어 | ⑤ 사람 판정 + 블라인드 비교 | "AI 검증"의 간판 화면. 키보드 UX |
| 코어 | ③ RAG 검색 + 챗 | 하이브리드 검색 + 도구 5개 에이전트. 부트캠프 직결 |
| 코어 (MVP) | ⑧ 진료 준비표 | "코드 집계 → LLM 해석". `make gate` 통과 시 착수 |
| 슬롯 | ② EOB 판독·대조 | VLM 판독 + 코드 대조. 코어와 독립 → 팀원용 |
| 슬롯 | ⑥ 리포트 + ⑦ 브리핑 | ⑧ 패턴 복제 |
| 슬롯 | ⑪ 재무 대조 에이전트 | 도구 루프 과제. 데이터 미설계 |
| 제외 | ⑨ 메신저 / ④ 방송 / ⑩ 동의서 / ⑫ 근태 | 범위 폭발 또는 AI 비중 낮음 |
| 제외 → 프로젝트 후 개인 확장 | 연쇄 치료계획·리콜 큐·임플란트 평생 한도·다회차 시술 회차 추적 | ⑧ MVP는 없이 성립. 생성기는 단발 내원 모델 |

## 3. 공통 원칙

1. **AI는 읽고 제안만, 쓰는 건 사람.** 원본 장부·차트에 AI가 직접 쓰지 않음
2. **숫자는 코드, AI는 해석.** 매출·건수·잔액은 쿼리로. LLM 출력의 숫자는 입력 fact에 있는지 **후검증**
3. **교차검증은 구조화 출력(① 분류)에만.** 자유 텍스트(요약·제안·답변)는 diff가 안 되므로 블라인드 비교로
4. **게이트웨이 모듈 하나.** 이름으로 호출, 폴백, 호출 로그(모델·토큰·지연·비용). 내부는 LiteLLM 라이브러리(서버 아님). 일일 비용 상한
5. **정답은 앱 DB 밖에.** 상세는 [[치과 AX - 평가 설계]] §1
6. **구조화 출력.** 분류·추출은 JSON 스키마 + 고정 enum
7. **스펙 → 평가셋 → 구현.** "프롬프트 수정 전 N% → 후 M%"를 `prompt_version`으로 기록

## 4. 코어 기능

> 각 기능: 목적 / 화면 / API / 완료 기준 / 설계 근거(왜 이렇게 하는지만)

### 가상 데이터 생성기

**목적**: 미니 EMR + 비정형(통화·문서·문자) + 정답을 시드 재현 가능하게 생성.

**산출물** (화면 없음)
- `app.sqlite` — `emr_*`(병원·직원·시술·환자·가족·예약·진료·수납·청구·문자) + `ax_*` 초기 적재(통화 전사·메타, 문서, 청크는 `make index`)
- `ground_truth/truth.sqlite` — 테이블은 [[치과 AX - 평가 설계]] §6
- `make data` / `make index` / `make verify` / `make fixture`(테스트용 small DB)

**완료 기준**
- `make verify` 필수 검사 전부 통과 — small과 large 둘 다
- 같은 시드 2회 → 테이블 내용 해시 동일(LLM 캐시 포함)
- 규모: large = `config/generator.yaml` 기본값

**설계 근거**: 정방향 시뮬레이션(TODAY까지 하루씩 예약·내원을 진행) — 사건이 시간 순서대로 일어나 시각·상태가 저절로 정합되고, 분포는 파라미터로 맞춘 뒤 경고로 확인.

### ① 통화 요약·분류

**목적**: 전사 1건 → 모델 A·B가 각각 요약 + 분류 JSON + 할 일 → 분류 불일치 표시.

**화면**
- 통화 목록(날짜·방향·상대·목적·엇갈림 배지) / 상세(전사 · A·B 요약·분류 나란히 · 불일치 강조)
- 입구: 생성 전사(기본) / **텍스트 붙여넣기 폼**(수신·발신 토글, 기본 수신) / 옵션(~1일): 동봉 샘플 녹음 3개 → `<audio>` 재생 → Whisper API 전사 → LLM 화자 구분 → 붙여넣기 폼

**API**
- `GET /calls`, `GET /calls/{id}`
- `POST /calls/paste` → 분류 2행 + 엇갈림 1행, 색인, 판정 큐 `pending`
- `POST /calls/{id}/classify`(재시도) / `POST /jobs/classify-batch`(`in_eval_pool` 일괄, `ax_jobs`)
- `POST /calls/transcribe-sample/{n}`(옵션)

**완료 기준**
- E2E: 붙여넣기 → `ax_call_classifications` 2행 `ok` → `ax_call_disagreements` 1행
- `in_eval_pool` 300 × A/B = 600행 `ok` (`in_eval_pool` 행 중, `active_prompt_version` 기준. 블라인드 풀은 판정 풀의 부분집합이라 별도 분류 없음)
- 분류 스키마: 목적 14 / 상대 6 / 급함 3 / 불리언 6 — enum은 [[치과 AX - 가상 데이터 생성 설계]] §4.1, 채점은 [[치과 AX - 평가 설계]] §2

**설계 근거**: 분류기 입력 제한은 [[치과 AX - 앱 설계]] §1. 복수 주제 통화는 주 목적 1 + 불리언 플래그(생성 제약은 가상 데이터 생성 설계 §4.1, 채점은 평가 설계 §2.2).

### ⑤ 사람 판정 + 블라인드 비교

**목적**: 사람이 분류를 판정해 정답지를 만들고, 요약을 블라인드로 비교.

**화면**
- **판정**: 전사 기본 노출(요약은 접힘, T) / 항목별 키 입력(목적 2자리, 나머지 1자리) → 자동 다음 항목 → Enter 저장·다음 건 / 메모 / 건너뛰기 / 상단 통계 / 엇갈림 배지
- **블라인드 탭**: 모델명 가린 두 요약(좌우 50:50 난수) → `1 / 2 / 비슷 / 둘 다 틀림`
- **정확도 표**: 항목별 모델 vs 사람 일치율(`prompt_version`별, n 표시), 블라인드 승률(모델 쌍별), 좌우 선택 비율. 모수는 **dev 판정만**(붙여넣기·test 제외 — [[치과 AX - 평가 설계]] §2.2). test 수치는 `eval.py --split test`에서만

**API**
- `GET /judge/next` / `POST /judgments` / `POST /calls/{id}/skip`
- `GET /blind/next` / `POST /blind-votes`
- `GET /metrics/accuracy?prompt_version=` / `GET /metrics/blind`
- `make export-human` / `import-human`(보존 키는 [[치과 AX - 앱 설계]] §7)

**완료 기준**
- Playwright: 키 시퀀스 10회 → `ax_judgments` +10, 블라인드 5회 → `ax_blind_votes` +5
- 정확도 뷰 2개 SQL이 행 ≥ 9(pytest)

**설계 근거**: 전사 기본 노출(A 요약을 읽고 판정하면 정답지가 A에 앵커링). 판정 풀·판정·블라인드 절차와 정확도 3종은 [[치과 AX - 평가 설계]] §2.

### ③ RAG 검색 + 챗

**목적**: 매뉴얼·공지·통화·문자를 하이브리드 검색, 도구 5개 단일 턴 에이전트가 "확인된 사실만" 답함.

**화면**
- **검색**: 질의 → `매뉴얼 결과` / `실제 사례 결과` 분리 + AI 요약. 출처(환자명·날짜) 노출
- **챗**: 질문 1 → 진행 이벤트(SSE) → 답변 + 출처 + 추천 질문 칩 3(클릭 = 새 질의). 멀티턴 없음. 답할 근거가 없으면 `refuse` 호출 → 앱이 고정 문구("문서함에 없음") 표시

**API**
- `GET /search?q=&source_types=&date_from=&date_to=` → `{manual_results, case_results}`
- `POST /chat`(SSE 진행 + 최종 답변) → `ax_search_logs`
- 도구 5개(시그니처는 앱 설계 §3): `search_docs`, `query_patient`, `query_schedule`, `query_claims`, `refuse`
- `make index` / `eval.py --split dev|test [--retrieval-only]`

**완료 기준**
- `eval.py --split dev` exit 0 + 리포트
- 데이터형 도구 선택 ≥ 3/6(dev), `--retrieval-only` Hit@5 ≥ 10/20(dev)
- 60문항 / 5유형, dev 30 / test 30. 질문 구성·채점 규칙·지표는 [[치과 AX - 평가 설계]] §3

**설계 근거**: 문서 청크가 전체의 4%라 단일 RRF에서 묻힘 → **문서 버킷·사례 버킷 따로 검색** 후 리랭커. 모든 청크에 출처 prefix 의무(환자명 없이는 사례형 검색 불가). 리랭커·임베딩 선택은 앱 설계 §7.

### ⑧ 진료 준비표 (MVP — `make gate` 통과 시 착수)

**목적**: 환자마다 5군데 뒤지는 걸 코드가 조인, LLM이 "오늘 권할 것" 한 줄.

**화면 (MVP)**
- 날짜 탭(최근 7일 + 오늘) / 칩 4개: **예약 · 보험 잔여(스케일링 미사용 성인) · 미수 잔액 · 가족 리콜 지남** / 환자 행 펼침(fact(환자 메모 포함) + 예정 시술 + 제안) / "다시 만들기"
- 여력 시: 필터, 인쇄 CSS. 제외: 복합 필터, "다음 진료일", "다른 치과 추정"

**API**
- `GET /prep?date=` / `POST /jobs/prep-regenerate?date=`(`facts_hash` 같으면 LLM 생략)
- 집계는 순수 함수 `prep_facts(date)`

**완료 기준**
- 집계 회귀 테스트·제안 후검증(`suggestion_valid`)·30명 사람 채점 — 규칙은 [[치과 AX - 평가 설계]] §4. 후검증 실패 시 null + 재시도
- 공수 4~5일

**설계 근거**: 출력을 `{text, used_facts}`로 강제 — 자유 문장에서 (키, 값) 역파싱은 불가능하므로 모델이 쓴 사실을 스스로 명시. 예정 시술은 `emr_appointments.planned_procedure_code`. 가족 리콜은 가족 구성원 `MAX(내원)+recall_cycle < sheet_date` 계산식. 치료계획·"다음 예약 없음" 칩은 프로젝트 후.

## 5. 슬롯 기능

### ② EOB 판독·대조
- **목적**: 보험 지급 통보서(스캔·팩스) 수백 줄을 VLM이 읽고 코드가 장부와 대조 → "확인 필요"만 사람에게
- **화면**: 배치 대시보드 / 결과 요약 카드(확정·금액 불일치·거절·장부에만·통보서에만) / 확인 필요 목록 → 원본 페이지 + 장부 vs 판독 + 판정(맞음·장부 수정·이의신청)
- **API**: `POST /jobs/eob-extract` → `ax_eob_lines` / `POST /eob/reconcile`(키 `(차트번호, 진료일, 시술코드, 치아번호)`, 결과 5종) / `GET /eob/review`, `POST /eob/review/{id}`
- **완료 기준**: 판독 재현율·대조 정확도·자동 확정률을 `truth_eob_lines` 대비 숫자로. 공수 1.5~2주
- **근거**: AI는 읽기만, 판정은 코드 — ⑤(사람이 채점)와 짝인 "코드가 검증" 사례. 판독 대상은 종이 통보서 스캔·팩스(디지털 원본 아님 → 열화·VLM 정합). VLM은 좌표가 부정확 → 하이라이트는 "페이지 N, 줄 M". 가상 데이터 생성은 [[치과 AX - 가상 데이터 생성 설계]] 슬롯 메모(조건부)

### ⑥ 경영 리포트 + ⑦ 아침 브리핑
- **목적**: ⑧ 패턴 복제. 월간은 모델 3개 합본 + 일치/불일치 표시
- **화면**: 리포트 목록·상세(그래프 + 본문 + PDF) / 브리핑 토스트(예약·신환·시술별·미확인·바쁜 시간) + TTS 버튼
- **API**: `POST /jobs/report?kind=&period=` → `ax_reports` / `GET /reports/{id}.pdf` / `GET /briefing?date=`
- **완료 기준**: 본문 숫자 전부 `metrics`에 존재(⑧ 후검증 재사용)

### ⑪ 재무 대조 에이전트
- **목적**: 가상 통장·카드 거래 ↔ 장부를 도구 루프로 대조
- **화면**: CLI 또는 채팅 1개
- **도구**: `get_bank_tx`, `get_card_tx`, `get_ledger`, `reconcile`, `pnl`, `breakeven`, `sql(readonly)`. 영수증 OCR은 ②의 VLM 재사용
- **완료 기준**: 의도적 불일치(영수증 누락·수수료·분할결제) 재현율
- **근거**: 데이터(`emr_bank_tx`, `emr_card_tx`, 지출)는 슬롯 착수 시 설계 — 기존 `emr_*`는 수정하지 않는 추가 테이블, 불일치는 통장·카드 쪽에만 심음([[치과 AX - 가상 데이터 생성 설계]] §2). 스킬 자동 저장은 제외

## 6. 진행 조건

생성·평가셋 작성의 순서 제약은 [[치과 AX - 가상 데이터 생성 설계]] §0·§5.1, [[치과 AX - 평가 설계]] §3.1.

**`make gate`** (스크립트 종료 코드. ⑧ 착수 조건)
1. ①·⑤·③ 완료 기준 전부(§4 — large DB, 캐시된 실모델 분류, dev 수치)
2. `next build` exit 0

`make ci`(매 커밋: small fixture + fake 게이트웨이 + pytest + verify + `next build` + Playwright)와는 다른 타겟.
